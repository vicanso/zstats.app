## 流程
1. 先看截图或代码，列出具体问题（层级、颜色、字体、对齐、信号矛盾），不要直接改
2. 每个问题写清"为什么不好 → 改成什么"
3. 只用下面的 tokens 修改，不临时发明新颜色或新字号（颜色写在 `palette.rs`，基础件在 `nsh/widgets.rs`）
4. 改完对照问题清单逐条确认

## 设计规则
- 层级靠明度区分，不靠描边：底 #1C1C1E，卡片 #252528，轨道 #36363A
- 文字三级：主 #F2F0EB / 次 #A19D96 / 弱 #8F8B85
- 只用一个强调色 #D9AE7A；选中态 = 16% 透明度底色 + 强调色文字，不用实心块
- 语义色只在有语义时出现：绿 #6EC48A = 正常，红 = 真有告警（没告警时铃铛保持灰色）
- 数字用系统字体 + 等宽数字特性；等宽字体只用于网速这类会快速跳动的值
- 主值大（20px），单位和明细小一级、颜色降一级
- 间距只用 4 / 8 / 10 / 12 / 16；圆角：窗口 14、卡片 12、按钮 7
- 最重要的状态放最上面；危险操作（退出）和普通操作分开
- 非核心入口（GitHub、关于）放进设置，不占工具栏
